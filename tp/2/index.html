Pregunta 1 — la casa que más separa MAE y RMSE: ListingId 781978 (NC, Wheatfield, OverallQual=9, 11 ambientes): real $357.100, predicho $583.271, error $226.171. Sacarla baja el RMSE 3,3% y el MAE solo 2,3%.

Conclusiones: (1) el salto grande no vino de la arquitectura sino de la codificación: sumar ubicación bien codificada bajó el MAE de 51 mil a 21 mil; (2) un error de codificación no da error (con District como entero el modelo entrena igual, solo peor); (3) restringir la capacidad mejoró la generalización.

Observaciones críticas para la defensa:

  • La celda de markdown del M4 dice “casi 300 mil parámetros” pero la salida real es 550.985.
  • “Cero sin indicador” dio mejor MAE en esta corrida; el notebook lo atribuye al ruido de una sola semilla y defiende la mediana por razones conceptuales (0 = “lote sin frente”, un valor fuera de la distribución). Para afirmarlo con números habría que promediar varias semillas.
  • Todas las variantes se comparan sobre test; en rigor, elegir entre variantes es trabajo de validación, y el test se abre una vez.
  • Faltan el M5, la Pregunta 5 escrita y el extra de pinball.

Misión missions/mlp (sobre las clases 3 y 4). Se entrega un único notebook ejecutado, que corra entero con Restart & Run All, con las explicaciones en celdas de markdown.

El cambio respecto de la clase: en clase la red respondía ¿está por encima de la mediana? (sigmoide, sí/no). Ahora la pregunta es ¿cuánto sale esta casa, en dólares?: cambia la última capa, la loss y las métricas. Y cambia la entrada: house-prices-extended.csv tiene 1460 casas, 19 columnas — las 10 numéricas de clase más State, District, HouseStyle, MonthSold, ListingId, LotFrontage (con faltantes), etc. Nada de eso entra a un Dense tal como viene.

Milestones:

  1. Tabla de decisiones: cada columna por el checklist de la clase (qué es, qué significa la resta, cardinalidad, puede faltar, la tengo al predecir). El dataset esconde al menos tres trampas de codificación.
  2. Baseline numérico con salida de regresión (par activación-loss correcto; saber por qué accuracy no significa nada) y MAE/RMSE en test.
  3. Categóricas: State (12) pide one-hot y District (72) pide embedding; el MAE tiene que bajar claro y mostrar cuánto aporta cada bloque.
  4. Que no memorice: overfitear a propósito y arreglar con L2 / dropout, con curvas train vs val.
  5. Tasar una casa escrita como la escribiría una persona: el preprocesamiento es parte del modelo.

Extra: P10/P50/P90 con pinball loss (≈80% de las casas entre P10 y P90).

Las cinco preguntas (lo que se corrige): (1) MAE vs RMSE vs MAPE y la casa que más los separa; (2) District como entero 0–71; (3) qué pasa con ListingId adentro; (4) con qué se imputa LotFrontage, 0 vs mediana, y si el faltante informa; (5) sobre qué datos se ajustó el escalador y qué número miente si se hace sobre todo el dataset.

Entregamos calveyra-desivo-giordanelli-rickert.ipynb (grupo Calveyra, Desivo, Giordanelli, Rickert), versionado en git con un commit por milestone (M1 a M4). El repo trae además el notebook de clase (house-prices.ipynb, el clasificador de AboveMedianPrice) y la consigna.

M1 — Tabla de decisiones. Primero inspeccionamos el dataset (dtype, valores únicos, faltantes): (1460, 20), LotFrontage falta en 103 filas (7,05%), State tiene 12 valores, District 72, HouseStyle 6, SaleCondition 5, CentralAir 2. La tabla tiene una fila por columna con la pregunta clave de la clase 4: ¿qué significa la resta entre dos valores? Identificamos las tres trampas:

  • ListingId — identificador único (1460 valores distintos): se descarta.
  • MonthSold — cíclica: diciembre y enero están a un mes, no a once → seno/coseno.
  • District — 72 categorías nominales: como entero 0–71 la red asume orden y distancia → embedding. El resto: numéricas con z-score, State/HouseStyle/SaleCondition one-hot, CentralAir 0/1, LotFrontage mediana de train + flag de faltante.

Particiones. train_test_split en dos pasos, 70/20/10 con random_state=42: train 1022, val 292, test 146. Partimos antes de calcular cualquier estadística; StandardScaler, mediana, encoders one-hot y el diccionario distrito→índice se ajustan solo con train. También escalamos el target (SalePrice va de ~50 mil a ~1,6 millones) con un StandardScaler de train y desescalamos las predicciones para reportar en dólares.

M2 — Baseline numérico. MLP Sequential: Dense(32, relu) → Dense(32, relu) → Dense(1, linear), optimizer='adam', loss='mse', metrics=['mae'], batch_size=32, 100 épocas. Comparamos tres imputaciones de LotFrontage (Pregunta 4), medimos si el faltante informa por sí solo, analizamos la casa con mayor error (Pregunta 1) y entrenamos una vez con ListingId adentro (Pregunta 3).

M3 — Categóricas. Pasamos a la API funcional de Keras: dos entradas, dense_features (numéricas + flag + one-hots + mes sin/cos + CentralAir) y district_idx (entero), que pasa por Embedding(73, 8) → Flatten → Concatenate con el resto → Dense(32) → Dense(32) → Dense(1, linear). El vocabulario es 72 + 1 índice reservado para distritos desconocidos (OOV). Entrenamos de forma incremental para medir el aporte de cada bloque, y la versión trampa con District como entero (Pregunta 2).

M4 — Que no memorice. Mismo feature set con una red sobredimensionada 512-512-512 (550.985 parámetros para 1022 casas), 150 épocas, sin freno. Después la misma red con L2 = 0,001 (kernel_regularizer), Dropout 0,3 entre capas y EarlyStopping(patience=15, restore_best_weights=True) sobre val_loss.

Lo que quedó pendiente: el notebook termina en el Milestone 4. No están el Milestone 5 (tasar una casa con el preprocesamiento dentro del modelo), la respuesta escrita de la Pregunta 5 (aunque el código aplica la regla correcta y lo comenta) ni el extra de pinball loss.

1Descartar ListingId como feature.Es un identificador único (1460 valores distintos): la resta entre dos IDs no significa nada y no hay nada que generalizar. Si el modelo ‘aprende’ de él, memoriza. Con el ID adentro el MAE de test casi no cambió (51.131 vs 51.411) pero la brecha val−train creció de 0,2657 a 0,3470.
2MonthSold codificado como sin(2πt/12) y cos(2πt/12).Es cíclica: diciembre (12) y enero (1) están a un mes, pero como número plano están a 11. Con dos floats los extremos del ciclo quedan juntos. Se necesitan los dos porque con solo el seno dos meses distintos darían el mismo valor.
3State (12 valores) con one-hot y District (72 valores) con embedding de dimensión 8.Regla de cardinalidad de la clase 4: hasta 15 valores one-hot, 50 o más embedding. One-hot deja todas las categorías a igual distancia (la verdad del dato) y no se aprende; el embedding aporta d=8 floats en vez de 72 y aprende de los datos qué distritos se parecen. Resultado: + State bajó el MAE de 51.411 a 30.956; + District a 25.380.
4Imputar LotFrontage con la mediana de train (70,0) más un flag binario LotFrontage_missing.Receta de la clase: imputar más flag, porque faltar puede significar algo. Lo comprobaron: las casas sin el dato valen en promedio 12% menos ($185.522 vs $210.880). Rellenar con 0 le dice a la red ‘esta casa tiene un lote sin frente’, un valor que no existe en la distribución real.
5Partición 70/20/10 con random_state=42, hecha antes de calcular cualquier estadística; scaler, mediana, encoders y mapa de distritos ajustados solo sobre train.Todo lo que se aprende de los datos se aprende solo del train. Ajustar μ y σ (o la mediana) sobre el dataset completo filtra información de test al entrenamiento y deja optimista el MAE/RMSE de test, sin ningún error visible.
6Salida Dense(1, activation='linear') con loss MSE; reportar MAE, RMSE y MAPE en dólares; no usar accuracy.La última capa la decide la tarea: un real → 1 neurona lineal + MSE/MAE/Huber. Una sigmoide acotaría la salida a (0,1). accuracy necesita clases que acertar; acá hay una distancia en dólares que minimizar.
7Escalar también el target SalePrice con un StandardScaler ajustado en train, y desescalar las predicciones.El precio va de ~50 mil a ~1,6 millones: sin escalar, la loss y los gradientes son enormes y la red no converge en 100 épocas con el learning rate por defecto de Adam (0,001). Las métricas se reportan después de inverse_transform, en dólares.
8Pasar de Sequential a la API funcional de Keras con dos entradas (dense_features y district_idx).El embedding necesita una rama propia: el entero no entra a la red, entra al lookup de la tabla Embedding, y su fila se concatena con el resto de las features antes de las capas densas.
9Overfitear a propósito con 512-512-512 (550.985 parámetros) y corregir con L2 0,001 + Dropout 0,3 + EarlyStopping(patience=15, restore_best_weights=True).Con 1022 casas, ~540 parámetros por ejemplo: memoriza (train 0,0121 vs val 0,1273). La guía de la clase: tabular → L2 + early stopping; red profunda → dropout + L2. Se combinaron las tres. Cortó a las 76 épocas y el MAE bajó a 16.538.
10Medir el aporte de cada bloque de columnas con entrenamientos incrementales (numérico → + State → + District → + resto).La consigna pide mostrar cuánto aporta cada bloque. Con la misma semilla y la misma arquitectura, la diferencia se atribuye a la información agregada: State −40%, District −18%, resto + mes cíclico −18%.
