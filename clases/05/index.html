Fundamentos

¿Qué es un prompt?

El prompt es la única palanca de control una vez elegido el modelo: como un ticket, si es vago, la implementación sale distinta.

BPE fusiona los pares de caracteres más frecuentes: lo común es un token, lo raro se parte. Cada familia de modelos tiene su vocabulario.

Economía de tokens

Se procesa y se factura en tokens, no palabras. El código y el JSON tokenizan peor que la prosa; centavos que se multiplican por miles de llamadas.

La fórmula del costo

Clave para el examen

Costo = tokens entrada × precio + tokens salida × precio. Cada turno reenvía todo el historial: un chat de 20 turnos paga el primero 20 veces.

Cómo funciona el caching

El caching guarda el cómputo de un prefijo, no respuestas. Si cambia un byte, todo lo posterior se recalcula: lo estable va adelante.

Limitaciones de los LLM

Clave para el examen

Tres fallas de familia: alucinaciones, no-determinismo y sesgo de recencia (importa más el principio y el final). Se administran con diseño, no con mejor modelo.

¿Por qué alucina un modelo?

El modelo genera el token más probable aunque no tenga el dato: no tiene un canal para decir «no sé», y lo inventado suena igual de seguro.

Model cascading

Clave para el examen

Model cascading: primero el modelo barato y, si la confianza es baja, se escala al caro. Todo el ahorro depende de que el gate sea confiable.

Palabras clave

Cascading: el gate en código

El gate es un campo confianza del esquema de salida, garantizado por structured outputs. Aun escalando 8 de cada 10, la cascada empata con el caro.

In-context learning (ICL)

Clave para el examen

In-context learning: el modelo toma el patrón de los ejemplos del prompt sin tocar los pesos. Zero-shot sin ejemplos, few-shot 2–10, many-shot decenas o cientos.

Zero-shot vs. few-shot

Mismo issue: en zero-shot el modelo inventa su escala y no se puede parsear; con dos ejemplos la escala deja de ser suya.

Many-shot learning

Many-shot: cuando few-shot no cubre la variabilidad. Cada error en producción se agrega como ejemplo: mejora continua sin reentrenar, con costo lineal en tokens.

Chain of Thought: pedir o mostrar el razonamiento paso a paso. Las mejoras publicadas son relativas a CoT, no precisión absoluta: leer bien los papers.

Self-consistency: muestrear varias cadenas del mismo prompt y votar por mayoría. Para alto riesgo; N llamadas cuestan N veces.

¿Por qué tardan más?

Más calidad es más tokens generados y más segundos: CoT 2–5× de latencia, self-consistency N× (en paralelo cuesta N en plata y 1 en tiempo).

Effort y thinking

Separador: controlar cuánto razona el modelo por parámetro, no por texto.

Thinking: el mecanismo

Clave para el examen

Thinking adaptativo: el modelo decide en cada pedido si piensa y cuánto. El código no puede asumir que siempre llega un bloque de thinking.

Palabras clave
Thinking (razonamiento extendido adaptativo)

Thinking: cómo queda en código

En código, display va dentro de thinking, y la respuesta es una lista de bloques: content[0].text se rompe si no hubo thinking.

Palabras clave
Thinking (razonamiento extendido adaptativo)

Una sola pasada, o una zona de trabajo aparte

Sin thinking, el modelo responde en una sola pasada: sin borrador ni verificación, y cada token emitido lo ata a lo que ya dijo.

Palabras clave
Thinking (razonamiento extendido adaptativo)Chain of Thought (CoT)

Qué cambia el bloque separado

El bloque separado es un borrador: puede equivocarse, verificar y cambiar de rumbo antes de la respuesta. No es una función de la interfaz.

Effort: un parámetro de la petición

Clave para el examen

effort es un parámetro de la petición (en output_config, no en thinking) que gradúa cuántos tokens gasta el mismo modelo. high es el default.

Cinco niveles, de rápido a exhaustivo. Afecta texto, tools y thinking: es una señal de comportamiento, no un presupuesto de tokens.
