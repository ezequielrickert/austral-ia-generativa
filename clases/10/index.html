Qué es un agente

Agenda: qué es un agente, el agente con LLM, tools, ReAct, otros tipos, multiagente y cuándo repartir.

¿Un LLM es un agente?

Quiz: un LLM por sí solo no es un agente. Recibe texto y devuelve texto; se vuelve agente cuando percibe y actúa en un loop.

Palabras clave
AgenteLLM (Large Language Model)

La definición de Russell & Norvig

Clave para el examen

Russell & Norvig: un agente es cualquier cosa que percibe su entorno con sensores y actúa sobre él con actuadores. Es la definición canónica.

Lo que la definición no menciona

La definición es amplia a propósito: no exige LLM, ni robot, ni inteligencia. Antes de diseñar, preguntá qué percibe, qué hace y en qué ambiente.

El agente racional

Clave para el examen

Agente racional: elige la acción que maximiza la medida de performance esperada con lo que percibió. Si la medida está mal especificada, hace algo indeseable.

Racionalidad: actuar bien según una medida

Sección 2: el agente basado en LLM.

Agente = LLM + planificación + tools

Lilian Weng: agente = LLM + planificación + tools (+ memoria). El LLM es el cerebro; tools y planificación organizan la clase.

Palabras clave

Dos formas de conectar un LLM con tools

Mismo LLM y mismas tools, dos formas: el código decide el próximo paso (pasos fijos) o lo decide el modelo en un loop.

Clave para el examen

Anthropic: workflow si el código fija el camino; agente si el LLM usa tools en un loop según lo que observa. Los sistemas reales mezclan las dos.

Los agentes tienen tools

Sección 3: los agentes tienen tools.

Qué es una tool

Clave para el examen

Una tool es una función que el agente pide: nombre, descripción y parámetros van al contexto. El LLM solo genera el pedido; el programa ejecuta.

Palabras clave
Uso de herramientas (tool calling)La descripción como disparador
Relacionadas
09·48MCP: una herramienta es una definiciónuna tool es una definición

Un contrato con un sistema no determinístico

Una tool es un contrato con un sistema no determinístico: puede llamarla de más, de menos o con argumentos raros. Se diseña pensando en quien la llama.

Palabras clave
Uso de herramientas (tool calling)no determinismo

Una tool en código

En código: @tool + docstring. El modelo ve el nombre, los tipos y el docstring, nunca el cuerpo. Ojo: eval() sobre texto del modelo es inaceptable en producción.

Palabras clave
Uso de herramientas (tool calling)langchain
Relacionadas
09·42Calcular: la misma cuenta por la APIla llamada vista desde la API

Principios para diseñar tools

Diseño de tools: pocas y consolidadas, nombres con prefijo, devolver contexto con significado y respuestas cortas. El contexto es caro y la memoria, barata.

Sección 4: ReAct.

ReAct: pensar también es una acción

Clave para el examen

ReAct suma el lenguaje a las acciones ($\hat A = A \cup L$): intercala pensamientos y acciones hasta poder responder. Razonar para actuar y actuar para razonar.

Palabras clave
ReActChain of Thought (CoT)
Relacionadas
05·37Chain of Thought (CoT)chain of thought

Una trayectoria ReAct

Una trayectoria de HotpotQA: los pensamientos descomponen la pregunta, extraen lo importante, reformulan cuando falla la búsqueda y sintetizan la respuesta.

Palabras clave
ReActtrayectoria

Las tools y la instrucción

En 2022, ReAct corría sobre modelos de completado (PaLM, davinci), sin roles; las tools eran tres líneas de texto en la instrucción.

Palabras clave
ReActIn-context learning: zero / few / many-shot

El prompt completo y el corte

Cada paso es una llamada de completado cortada antes de Observation; el código ejecuta la acción, pega el resultado y repite hasta Finish o 7 pasos.

Plan-and-Execute: planificar primero

Clave para el examen

Plan-and-Execute: un planner escribe el plan completo, los executors (pequeños ReAct) resuelven cada paso y un re-planner decide si sigue o replanifica.

Qué gana y qué cuesta planificar

Planificar ahorra llamadas al modelo grande y fuerza a pensar la tarea entera, pero las ventajas no están medidas y el plan no conecta datos entre pasos.

Reflexion: intentar, evaluar, reflexionar

Clave para el examen

Reflexion: el Actor intenta, el Evaluator juzga y, si falla, se escribe una crítica en lenguaje natural como memoria para el próximo intento. No toca los pesos.

Palabras clave
Reflexionmemoria

Una reflexión, en código

Ejemplo: una solución que solo cuenta paréntesis falla los tests que generó el propio agente; la reflexión dice «importa el orden» y guía el siguiente intento.

Palabras clave
Reflexiontests

Qué gana y qué cuesta reflexionar

Reflexion llegó a 91 % en HumanEval (vs 80,1 % de GPT-4), pero necesita una señal clara de éxito y cuesta varios intentos.

Palabras clave
ReflexionEvals (eval set propio)

ReWOO: planificar con variables

Clave para el examen

ReWOO: el plan se escribe completo con variables (#E1) y todas las tools se ejecutan sin volver a razonar. El LLM piensa solo al planificar y al resolver.

Palabras clave
ReWOOplanificacion

Un plan ReWOO

En el plan ReWOO, E4 usa el resultado de E2 sin conocerlo todavía. Un LLM puede ser una tool (LLM[...]): una llamada al planner, cinco ejecuciones y un solver.

Palabras clave
ReWOO

Qué gana y qué cuesta planificar con variables

ReWOO ataca el costo: en ReAct cada paso reenvía el prompt acumulado. A cambio, si una tool devuelve algo inesperado, nadie replanifica.

Palabras clave
ReWOOCosto por token / fórmula del costo

Qué es un sistema multiagente

Clave para el examen

Multiagente: varios agentes que interactúan para un problema que excede a uno. Repartir mueve tres palancas: paralelismo, especialización y aislamiento de contexto.

Forma básica: un orquestador parte la tarea en el momento y cada worker resuelve su parte con su propio loop.

Sección 7: cuándo repartir.

El precio de paralelizar

Un agente gasta ~4× los tokens de un chat; un multiagente, ~15×. El 80 % del desempeño en BrowseComp se explica por tokens: solo paga si la tarea vale.

Palabras clave
Costo por token / fórmula del costoSistema multiagente
Relacionadas
05·8La fórmula del costola fórmula del costo

Cómo fallan

MAST: 1.642 trazas de 7 sistemas, entre 41 % y 86,7 % de fallas. Tres categorías: especificación, desalineación entre agentes y verificación.

Palabras clave
MASTEvals (eval set propio)

El aislamiento hay que configurarlo

Al pasar el control, el que recibe suele heredar toda la conversación. El aislamiento no viene solo: hay que configurarlo y verificarlo en los logs.

Palabras clave
Aislamiento de contextohandoff

Compartir el contexto no alcanza

Aun con todo el contexto compartido, cada subagente no ve las decisiones de su hermano, y chocan al combinar (el Flappy Bird de Cognition).

El debate: ¿construir multiagentes?

Cognition («no construyas multiagentes»: un solo hilo) vs. Anthropic (a favor para investigación), con un día de diferencia. Discuten si los agentes necesitan verse.
