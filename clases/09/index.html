Sección 1: pre-training.

Pre-training: completar texto

Clave para el examen

El pre-training minimiza la pérdida del siguiente token sobre texto web, sin etiquetas (auto-supervisado). Sale un modelo base: sabe mucho, pero no sigue instrucciones.

Qué es Common Crawl

Common Crawl: archivo público de la web desde 2008, base de casi todos los datasets abiertos (60 % de GPT-3). Mayormente es ruido: menús, errores y duplicados.

C4: cómo Google depuró Common Crawl

C4: Google filtró Common Crawl con reglas a mano, y el mismo modelo rinde mejor en todas las tareas. Filtrar datos funciona, aunque tiene costos.

Cómputo de entrenamiento: $C \approx 6ND$ (N parámetros, D tokens; 2 FLOPs adelante, 4 atrás). La ley de escala dice qué N y D convienen para un C dado.

Chinchilla: 20 tokens por parámetro

Clave para el examen

Chinchilla: con el mismo cómputo, conviene un modelo más chico con más datos, unos 20 tokens por parámetro. Hoy se entrena muy por encima (Llama 3 8B, ~100×).

¿Cuánto más puede crecer?

Los datasets crecen ~2,4× por año y se agotaría el texto humano público hacia 2028. Pagar a personas para escribir no alcanza.

Problemas de los datos: la lista negra de C4 sesga contra dialectos, el inglés domina (89,7 % vs 0,13 % de castellano) y crece el texto generado por modelos.

Quiz: ¿qué va a responder?

Quiz: el modelo base puede seguir con otra pregunta, una receta o la respuesta. Las tres son continuaciones plausibles; no sabe que se espera una respuesta.

Supervised Fine-Tuning

Sección 2: Supervised Fine-Tuning (SFT).

SFT: Supervised Fine-Tuning

SFT sigue entrenando el modelo base con pares (prompt, respuesta) escritos por personas: decenas de miles, no billones de tokens. El modelo que sale conversa.

Palabras clave
SFT (Supervised Fine-Tuning)demostraciones

Constitutional AI: principios en vez de anotadores

Constitutional AI (Anthropic, 2022): el modelo critica y corrige sus propias respuestas según principios escritos, y el SFT se hace con las versiones corregidas.

Palabras clave
Constitutional AISFT (Supervised Fine-Tuning)

GPT-3 antes y después del post-training

El mismo GPT-3 antes y después del post-training: sin post-training, sigue el texto como si fuera un examen. Cambia el formato, pero no garantiza que sea correcto.

post trainingSFT (Supervised Fine-Tuning)

Datos de demostración

Clave para el examen

SFT usa la misma cross-entropy del siguiente token, pero sobre demostraciones y con la pérdida solo en los tokens de la respuesta. Es behavior cloning: copia el comportamiento.

Un dataset de SFT es un JSON con dos campos, prompt y respuesta. Hay públicos: Dolly-15k, OpenAssistant, Alpaca (generado con ChatGPT).

Reinforcement Learning from Human Feedback

Sección 3: RLHF, aprender de preferencias humanas.

RLHF en dos pasos

RLHF en dos pasos: entrenar un juez (reward model) con preferencias de personas y después mejorar el LLM contra ese juez.

Palabras clave
RLHFReward model

RLHF: puntuar y reforzar

Clave para el examen

RLHF: con 100 mil a 1 millón de comparaciones se entrena el reward model; después el LLM se ajusta para sacar puntajes altos con solo prompts.

Palabras clave
RLHFReward modelPPO y penalización KL

Paso 1: comparar es más fácil que escribir

Comparar dos respuestas es más consistente que escribirlas o puntuarlas. Aun así, los anotadores coinciden ~73 %: el modelo se alinea a un grupo concreto de personas.

Palabras clave
preferenciasanotadores

Paso 1: el reward model

Clave para el examen

El reward model es el modelo SFT con una salida escalar: recibe (prompt, respuesta) y aprende a puntuar más alta la respuesta elegida.

Palabras clave
Reward modelRLHF

Paso 1: el reward model, en un batch

En un batch, cada par entra como dos secuencias con padding. La pérdida $-\log\sigma(r_A - r_B)$ baja cuando la preferida puntúa más.

Palabras clave
Reward modelBatch (lote)

Paso 2: optimizar con PPO

Clave para el examen

PPO: el LLM genera, el RM puntúa y se ajusta con un freno KL que lo ata al SFT. Es caro e inestable; DPO llega a lo mismo sin RM.

Palabras clave
PPO y penalización KLDPO (Direct Preference Optimization)Reward hacking

Sección 5: herramientas.

Las piezas de una plataforma

Por API, el modelo nunca ejecuta: la plantilla pasa JSON a texto con tags y un parser lo revierte. La herramienta corre en tu app o en la plataforma.

Palabras clave

El circuito con un agente

Clave para el examen

El chat es el agente: llama al LLM, ejecuta las tools pedidas, agrega el resultado con rol tool y repite hasta que el LLM responde. Pone un tope de vueltas.

Sección 6: fine-tuning.

Dónde entra el fine-tuning

Clave para el examen

El fine-tuning repite el post-training a escala chica con datos propios. LoRA congela los pesos y entrena dos matrices chicas; QLoRA además guarda el modelo en 4 bits.

Palabras clave
Fine-tuning (del equipo de producto)LoRAQLoRA
Relacionadas

Prompt, RAG o fine-tuning

Clave para el examen

RAG corrige fallas de información; el fine-tuning, fallas de comportamiento (forma, formato, estilo). Orden: prompt → ejemplos → RAG → fine-tuning.

Palabras clave
RAG (Retrieval-Augmented Generation)Fine-tuning (del equipo de producto)Prompt / prompt engineering

Cuándo vale la pena el fine-tuning

El fine-tuning paga cuando el prompt ya no alcanza: un formato fijo (JSON), un estilo, una tarea poco vista o destilar en un modelo chico.

Palabras clave
Fine-tuning (del equipo de producto)destilacion

Fine-tuning en la nube

Fine-tuning administrado (sept. 2026): Azure y Google lo ofrecen; OpenAI cierra a usuarios nuevos. En todos se sube un JSONL, se lanza el trabajo y sale un modelo propio.

Palabras clave
Fine-tuning (del equipo de producto)nube

Fine-tuning local: el recorrido

Fine-tuning local con pesos abiertos: TRL/PEFT o Unsloth en una GPU propia o en Colab. Sale un adaptador aparte, con la máscara −100 antes de la respuesta.
