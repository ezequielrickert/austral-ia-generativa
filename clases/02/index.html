El repo como contexto

Sección 2: el repo como contexto.

El modelo responde de memoria

El modelo no conoce tu repo: responde de memoria. Por in-context learning, la calidad del agente depende del contexto que le llega.

Palabras clave
In-context learningContexto > prompting
Relacionadas
01·9El chat responde de memoria Compl.El mismo argumento, en la clase 1

Qué lee el agente al pararse en el repo

No carga el repo entero: lo explora con herramientas (árbol, README, configs, grep, git log). El orden del repo es contexto.

Palabras clave
El repo como contexto

Markdown, el formato del ecosistema

Contrato, Skills y subagentes son .md con frontmatter YAML: el modelo los lee nativo y entran en diffs, commits y PRs como el código.

Palabras clave
Markdown con frontmatter

El conocimiento del proyecto en .md

Regla: lo que el agente deba saber va en .md dentro del repo: memoria, especificaciones (SPEC.md) y conocimiento general.

Palabras clave
SPEC.mdEl repo como contexto

MCP servers

Sección 6: MCP servers.

Qué es MCP

Clave para el examen

MCP: estándar abierto en el que un server expone las acciones de un servicio (GitHub, base de datos, deploy) como tools que el agente llama dentro de su loop.

Palabras clave
MCP (Model Context Protocol)Uso de herramientas (tool calling)
Relacionadas
06·46MCP conecta modelos con herramientas

Cómo el agente descubre y usa una herramienta

Al conectar un server, el agente recibe el catálogo (nombre, descripción, parámetros) y elige por descripción. Cuándo conviene cada tool lo dice la documentación.

Palabras clave
MCP (Model Context Protocol)La descripción como disparador
Relacionadas
06·54El ciclo de vida de una herramienta MCPEl ciclo de vida de una tool MCP

El ecosistema MCP para desarrollo

Casi todo el toolchain ya tiene server MCP: GitHub, Postgres, Playwright, Sentry, Jira, Figma, Context7 e infraestructura de deploy.

Palabras clave
MCP (Model Context Protocol)toolchain

Dónde buscar servidores MCP publicados

Primero los catálogos oficiales (Claude, ChatGPT), después repos y directorios comunitarios. Siempre mirar quién publica el server.

Palabras clave
MCP (Model Context Protocol)confianza

Projects

Sección 3: Projects.

Qué es un Project

Clave para el examen

Project: espacio autocontenido con carpeta, memoria e instrucciones. Los chats del Project no comparten contexto entre sí, solo instrucciones y knowledge base.

Palabras clave
projectEl repo como contexto

Conceder una carpeta y ver el contexto

Cowork solo ve la carpeta concedida: esa carpeta es el control de privacidad. Usar una dedicada y nunca datos sensibles.

Palabras clave
Mínimo privilegioprivacidad

¿Los lee todos?

Clave para el examen

Con pocos archivos los lee completos (precisión, pero llena la ventana); con muchos, busca y lee lo relevante. No elegís el modo: elegís qué material entra.

Skills

Sección 4: Skills.

Qué es una Skill

Clave para el examen

Una Skill es un instructivo escrito en español, no código: se enseña una vez y la tarea sale siempre igual. Un trabajo por Skill.

Palabras clave
Skill

Cómo se usa una Skill

Explícita con /informe-mensual o automática cuando el pedido coincide con la description: la descripción decide si se activa sola.

Palabras clave
La descripción como disparadorSkill

Tres formas de crear una Skill

Tres caminos para crear una Skill: desde el panel, desde el prompt o grabando la pantalla mientras hacés la tarea.

Palabras clave
Skillcrear skill

Metodo 1: Crear desde el panel

Configuración → Habilidades → Agregar: «Crear con Claude», «Escribir las instrucciones» o «Grabá tu pantalla». Importar una Skill es otra cosa.

Palabras clave
Skillcrear skill

Metodo 2: Crear desde el prompt

Pedir la Skill en el chat; Claude pregunta por el proceso. Contalo con el detalle que necesitaría alguien capaz que nunca hizo la tarea.

Palabras clave
Skillcrear skill

Metodo 3: Crear grabando una Skill

Grabar la pantalla haciendo la tarea y narrándola; Claude mira la grabación y propone la Skill. Ideal para lo que tenés «en los dedos».

Palabras clave
Skillcrear skill
